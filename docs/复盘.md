## 三、遇到的问题

| 问题 | 原因 | 解决方案 | 下次避免 |
|---|---|---|---|
| 不打开应用右键无效 | 宿主未运行，扩展通知无人接收 | App Group 待处理请求 + NSWorkspace 自动拉起 | 后台代理应用必须设计“唤醒”路径 |
| 扩展拉起宿主总失败 | 宿主路径计算少退一级目录（.appex→PlugIns→Contents→.app） | 向上查找 .app 并加回归测试 | 路径计算用测试锁定 |
| 启动后设置窗口延迟约 1 分钟 | 测试时直接改写 App Group plist，cfprefsd 卡死 | 重启用户级 cfprefsd；代码改为后台线程读取偏好 | 永不直接改 cfprefsd 管理的 plist |
| 气泡内点击复制无效 | LSUIElement 后台应用的气泡点击被系统当作激活点击吞掉 | 改为行内显示完整路径 + 卡片内点击 | 后台代理应用避免依赖气泡交互 |
| 菜单栏房子图标看不到 | iBar 菜单栏管理器把第三方图标收入隐藏区 | 用户在 iBar 中显示；卡片齿轮/启动台兜底 | 交付时说明菜单栏管理器影响 |
| GitHub 下载/推送极慢或断连 | 本机访问 github.com 直连不稳，Clash 代理对 GitHub 返回 404 | 镜像下载 + 官方 SHA-256 校验；API 直连；重试推送 | 中国网络发布 GitHub 走镜像+校验流程 |
| 用户把设备码输进搜索框、代码 15 分钟过期 | 引导不足、设备码有效期短 | 直接在浏览器打开 login/device 页再输入新码 | 引导给完整 URL，强调不是搜索 |
| 后台轮询进程被会话回收 | nohup 子进程随 exec 会话结束被杀 | 改用持久会话运行轮询 | 长轮询用持久会话 |
| gh 登录失败 | 设备码 scope 缺 read:org | 用 repo,read:org 重新授权；或绕过 gh 直接用 API | 一次授权带全 scope |
| 推送误报成功 | git push 管道退出码被 tail 吞掉 | set -o pipefail 重写重试循环 | 判断命令成功看真实退出码 |

## 四、关键错误总结

1. 路径计算“少退一级”是本次最典型的低级错误，靠回归测试根治。
2. 测试手段（直接写 plist）污染了系统服务状态，教训是测试要贴近真实调用路径（走 cfprefsd）。
3. 网络问题消耗了大量时间，根源是缺少“中国网络发布 GitHub”的既定流程，应沉淀为 skill。
4. Finder 扩展热加载不稳定（改扩展后菜单可能缺失），需要 pluginkit 重注册 + 重启 Finder + 宿主启动一次的标准刷新序列。

## 五、可复用经验

- 扩展→宿主消息：先写 App Group 待处理请求，再拉宿主，宿主启动时消费；避免通知丢失。
- 非激活面板内交互：点击、按钮可靠；SwiftUI popover 交互不可靠。
- 点击外部关闭：只对“其他应用”生效，本应用自己的窗口不误关。
- 中国网络发布 GitHub：api.github.com 直连可用；下载用镜像 + 官方 checksum；device flow 授权后立即用持久会话轮询；`set -o pipefail` 判断推送结果。
