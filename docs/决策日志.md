# Finder 快速导航决策日志

## 2026-08-06：选择低遮挡方案 C

- 项目目标：在 Finder 文件夹空白处右键完成快速导航和新建文件。
- 用户选择：方案 C。
- 关键原因：卡片应紧贴右键位置，减少选择菜单后继续移动鼠标的距离。
- 新增约束：卡片不能大面积盖住文件夹内文件。
- 放弃方案：A 的独立浮动面板需要额外移动；B 的持续侧边栏占用 Finder 空间。

## 2026-08-06：卡片采用紧凑分页结构

- 决策：目标尺寸约 `292 × 286 pt`。
- 决策：收藏和最近访问使用两个分页，不同时展开。
- 决策：新建文件从卡片中移出，保留为背景右键的独立子菜单。
- 理由：降低卡片高度和文件遮挡，同时保持最初右键菜单结构。

## 2026-08-06：采用四候选位置评分

- 候选：光标右、左、下、上。
- 优先级：屏幕可见 > Finder 窗口外 > 与内容区域重叠更少 > 鼠标距离更短。
- 降级：拿不到 Finder 窗口边界时，只依据屏幕可见区域避让。

## 2026-08-06：正式实现采用 Finder Sync + 宿主 NSPanel

- Finder Sync Extension：背景右键菜单、当前目录、触发请求。
- 宿主应用：非激活 NSPanel、定位、导航、权限、收藏、最近访问和新建文件。
- 理由：Apple 明确指出 Finder Sync 不是通用 Finder UI 注入框架；复杂面板不放在扩展进程中。
- 风险：`NSExtensionContext.open` 是否被 Finder Sync 扩展点支持必须实机验证。
- 降级：自定义 URL 失败时，使用 App Group 共享请求数据和受限进程间通知。

## 2026-08-06：沙盒扩展使用 POSIX 账户目录作为监听根目录

- 现象：Finder 扩展只有启用 App Sandbox 后才能稳定注册，但 `FileManager.default.homeDirectoryForCurrentUser`、`NSHomeDirectory()` 和环境变量 `HOME` 都变成扩展容器目录。
- 决策：使用 `getpwuid(getuid())` 读取真实账户主目录，环境变量和 Foundation 主目录仅保留作诊断/回退。
- 理由：统一日志已证明账户目录为 `/Users/mac`，并且使用它后 Finder“文稿”空白处出现“快速导航”。
- 验证：回归测试通过；实机点击日志正确记录 `/Users/mac/Documents` 和鼠标坐标 `{585, 317}`。
- 禁止回退：不要再次把 `directoryURLs` 设置为沙盒中的 `HOME` 或 `NSHomeDirectory()`。

## 2026-08-06：放弃 Finder Sync 自定义 URL 唤起

- 实测：扩展生成的 `finderquicknav://show` 请求内容正确，但 `FIFinderSyncController.open` 连续 3 次返回 `false`，宿主未收到事件。
- 决策：满足计划中的失败阈值，停止继续调 URL 注册，改用可实机验证的本机 IPC。
- 保留：URL builder 和 smoke test 暂留作可复现证据；正式协议完成后再整理。

## 2026-08-06：采用分布式通知作为点击事件 bridge

- 参考：定向学习 `wflixu/RClick` 后确认，Finder Sync 与常驻宿主可使用 `DistributedNotificationCenter` 传输 Codable 消息；App Group 更适合持久设置共享。
- 决策：本项目独立实现单向、按需发送的 JSON 点击消息，不使用 App Group，不启用心跳轮询。
- 理由：本地自签名无需额外 entitlement；三次实机发送和接收均成功；符合宿主空闲时不轮询约束。
- 安全边界：正式协议必须增加时效、来源上下文、路径和重复消息校验，不能直接信任任意分布式通知。
- 许可：RClick 为 GPL-3.0，只学习架构，不复制代码。

## 2026-08-06：导航按权限边界分层实现

- 决策：返回和上一级使用辅助功能键盘事件；收藏/路径跳转使用 Finder Apple Event 设置当前窗口 target。
- 安全：先检查 Finder 是否前台、目标是否为真实目录、辅助功能是否已授权；失败返回结构化错误，不静默新开窗口。
- 错误映射：`-1743` 为 `automationDenied`，无窗口为 `noFinderWindow`，其他 Apple Event 状态保留原始码。
- 实测：当前 `accessibilityGranted=false`；点击返回和上一级均安全返回 `accessibilityDenied`，未发出键盘事件。
- 后续：等待用户在系统设置授予 `/Users/mac/Applications/FinderQuickNav.app` 辅助功能权限，再进行真实导航验收。

## 2026-08-06：完成 Finder 导航可行性闸门

- 实测：用户授权后，同一 Finder 窗口依次完成上一级、返回、跳转 `/Users/mac/Documents/Codex`，窗口数量没有增加，最后恢复到“文稿”。
- 前台处理：工具操作环境可能使 Codex/ToDesk 成为系统前台；动作执行前先激活 Finder，再确认前台，避免快捷键落到错误应用。
- 结论：Task 1 五项闸门全部通过，正式实现可以进入请求协议和状态存储，不再停留在 spike。

## 2026-08-06：桥接消息升级为正式请求协议

- 决策：请求包含 `action`、UUID、文件 URL、鼠标坐标和 `Date`；宿主解码时限制时间窗口、验证本地目录和有限数值，并拒绝重复 UUID。
- 理由：分布式通知本身不提供业务语义和防重放，正式卡片入口必须在宿主边界重新校验。
- 验证：5 类非法请求测试通过；协议版应用部署后合法 Finder 点击仍能显示卡片。

## 2026-08-06：收藏与最近访问采用 UserDefaults JSON 存储

- 决策：收藏和最近访问只保存规范化本地目录路径；收藏保持加入顺序，最近访问最多保留 8 项且重复访问移到顶部。
- 理由：首版数据量小，不引入数据库或 App Group；宿主沙盒关闭，UserDefaults 可直接持久化。
- 验证：跨 store 实例读取、去重、删除、上限和真实卡片分页均通过。

## 2026-08-06：新建文件采用独立 action 菜单和独占创建

- 决策：Finder 扩展在背景右键中保留独立“新建文件”子菜单，宿主通过正式 bridge action 创建文件夹、TXT、Markdown、Word、Excel 和 PowerPoint。
- 决策：普通文件使用 POSIX `O_CREAT | O_EXCL` 独占创建，冲突时生成 `未命名 2`、`未命名 3` 等名称，避免覆盖已有对象。
- 决策：DOCX/XLSX/PPTX 作为打包资源复制，不依赖用户安装 ONLYOFFICE；资源由可复用 Swift 生成脚本产生，并由 `unzip -t` 验证。
- 理由：菜单入口符合已确认的产品结构，独占创建可以处理同名文件竞争，模板资源让首版可离线运行。
- 验证：服务 smoke test、模板 ZIP 检查、Finder TXT/Word 实机点击和 Finder 选中动作均通过。

## 2026-08-06：本机交付副本保持单一注册并可恢复

- 决策：运行副本固定为 `/Users/mac/Applications/FinderQuickNav.app`；每次替换前把旧副本移动到 `FinderQuickNav/system/archive/`，不永久删除。
- 验证：新版本深度签名、宿主/扩展版本一致，`pluginkit` 只登记一个启用扩展；集成测试临时文件也已归档。

## 2026-08-06：设置窗口采用平铺式原生模块

- 决策：主应用提供快速导航、个人收藏、新建文件和权限与扩展四个设置模块；`发送到` 只保留后续版本说明，不提前加入可用入口。
- 理由：用户希望像超级右键一样进入软件统一编辑偏好；四个模块覆盖当前已确认需求，同时保持卡片紧凑。
- 验证：设置路由 smoke test 通过；真实窗口可以切换模块，收藏页和新建文件页均可编辑。

## 2026-08-06：通过 App Group 共享新建文件菜单配置

- 决策：宿主和 Finder 扩展共同使用 `group.local.finderquicknav`；扩展菜单根据共享配置生成启用项目和顺序，全部关闭时隐藏新建文件父项。
- 理由：设置窗口修改必须跨进程影响 Finder 右键菜单；App Group 只用于持久配置，瞬时点击事件继续使用已验证的分布式通知 bridge。
- 验证：两个 entitlement、工程引用、共享 store 和菜单读取均通过静态/编译检查；真实扩展日志确认 App Group 容器 lookup 成功。

## 2026-08-06：本机 App Group 构建采用无签名构建后本地重签

- 现象：当前本机没有开发者 provisioning profile，带 App Group entitlement 的普通 Xcode 直签在 `GatherProvisioningInputs` 阶段失败。
- 决策：保留 entitlement，不降低功能；`scripts/build-local.sh` 先执行 `CODE_SIGNING_ALLOWED=NO` 的 fresh build，再用现有 `FinderQuickNav Local Signing` 分别重签宿主和扩展，并执行深度验证。
- 边界：这是本机开发交付方案，不等同于正式发布签名、公证或 App Store 分发；正式团队环境应配置 Apple Developer profile。

## 2026-08-06：部署时按扩展路径注册并清理重复副本

- 现象：把同一个 bundle ID 的旧 `build-release` 副本和 `/Users/mac/Applications` 副本同时注册，会导致 Finder 菜单刷新和 bridge 消费出现重复。
- 决策：安装脚本只注册 `FinderQuickNav.app/Contents/PlugIns/FinderQuickNavExtension.appex`，`verify-extension-registration.sh` 强制要求同一 ID 只有一个注册项；旧副本移动到 `system/archive/` 或通过 `pluginkit -r` 移除注册。
- 验证：当前注册输出只有 `/Users/mac/Applications/FinderQuickNav.app` 一项；双宿主问题已定位并清理。

## 2026-08-07：分页状态属于一次卡片会话

- 现象：在“最近访问”中点击目录后，卡片重建视图并跳回“收藏”；用户需要重新选分页。
- 决策：把当前分页放进 `QuickNavSessionState`，导航只更新目录，分页选择通过回调写回会话；重新打开卡片时才读取设置中的默认分页。
- 理由：收藏和最近访问是两个独立工作流，导航不应改变用户正在浏览的工作流。
- 验证：导航 smoke test 覆盖“最近访问保持最近访问”和“收藏保持收藏”，通过。

## 2026-08-07：主应用采用“man导”可见身份

- 决策：可见产品名使用“man导”，保留 `FinderQuickNav` 作为工程/Bundle 可识别名；移除宿主 `LSUIElement`，使其成为可从启动台打开的正常应用。
- 决策：初次启动与重新打开时显示设置窗口，设置窗口标题统一为“man导 设置”。
- 决策：图标采用用户提供的企鹅少女图；资源进入 AppIcon asset catalog。
- 验证：App identity smoke test、Debug fresh build、图标编译、深度 codesign 和 Computer Use 启动窗口读取均通过。
- 额外注意：`pluginkit` 注册有短暂异步延迟，安装脚本必须等待并重试后再做唯一扩展断言。

## 2026-08-07：用户图标截图采用精确裁切而非重绘

- 现象：图标截图左侧包含相邻图标的窄条，直接缩放后会进入 AppIcon。
- 决策：裁去左侧残片后再无感轻微缩放为正方形，保留人物、光圈、配色和原有图像质感。
- 理由：这是一处确定的截图边缘问题，精确裁切比生成式修图更可控，也不会改变角色脸部。
- 验证：源图与清理预览均保存；工程生成的 `Assets.car` 含 1024×1024 AppIcon rendition，安装副本通过 codesign 与扩展注册校验。

## 2026-08-07：AppIcon 使用真实透明圆角轮廓

- 现象：用户最新提供的图标 PNG 没有 alpha 通道，白边和棋盘格是截图像素；仅裁去相邻图标残片仍会在启动台图标周围显示异常背景。
- 决策：不再生成式修图。使用 `prepare-user-app-icon.swift` 裁去右侧 54 px 的截图残留，再以 260 pt 圆角轮廓写出 RGBA PNG，并从这份 1024 主资源导出所有 AppIcon 尺寸。
- 理由：用户要求“只要图片本身的形状”。确定性处理能精确保留角色、光圈和原图颜色，同时真正清除外部像素。
- 验证：旧图标回归脚本先在角落 alpha=255 和右缘白色截图样点处失败；新资源通过透明轮廓测试，7 个尺寸均有 alpha，fresh build、codesign、安装和唯一扩展注册通过。

## 2026-08-07：宿主改为后台代理程序并支持右键自动拉起

- 背景：用户不打开应用时右键无效，打开后 Dock 又占一个格子；希望像超级右键一样后台常驻。
- 决策：`LSUIElement=true`（不占 Dock、不进 Cmd-Tab，仍可从启动台打开设置）；扩展侧在点击“快速导航/新建文件”时先把请求写入 App Group，宿主未运行则用 `NSWorkspace.openApplication(activates:false)` 拉起；宿主启动时消费待处理请求则只弹卡片，无请求才弹设置窗口。
- 关键修复：宿主路径计算原少退一级目录（`.appex → PlugIns → Contents → .app` 需要三级），统一改为向上查找 `.app` 并加回归测试；沙盒扩展内 `openApplication` 经带沙盒签名的测试体验证可用。
- 验证：真实 Finder 右键点击后宿主自动启动且只有卡片窗口；普通启动弹设置窗口；扩展注册唯一、深度签名通过。
- 后续：如需开机自启可增加登录项开关（SMAppService），本轮未加。

## 2026-08-07：完整路径改为行内悬停显示，点击即复制

- 现象：SwiftUI 气泡（popover）在后台代理程序（LSUIElement）中不可点击——点击被系统当作激活点击吞掉，多次真机实测均无法触发复制或层级跳转。
- 决策：放弃气泡方案，改为悬停时路径行内直接显示完整路径并展开 `/ › Users › mac › Documents` 层级按钮；点击路径文字或行任意位置复制当前文件夹完整路径到剪贴板并显示“已复制”。
- 决策：点击外部关闭与“其他应用激活关闭”改为只对非本应用窗口生效，避免点击本应用自身窗口（路径层级、设置窗口）时误关卡片。
- 验证：真实卡片悬停显示完整路径与层级；点击后 `pbpaste` 返回当前文件夹路径；复制服务有独立 smoke test。

## 2026-08-07：系统权限现状与授权边界

- 核查：TCC 数据库中 `AppleEvents`（自动化控制 Finder）与 `DocumentsFolder` 已为允许；完全磁盘访问未授予，下载/桌面等首次使用会弹窗。
- 决策：由用户本人在系统设置“完全磁盘访问权限”中完成授权（必须输入密码/Touch ID，第三方无法代操作）；授权后进入任何文件夹都不再询问。

## 2026-08-07：偏好设置入口采用菜单栏图标 + 卡片齿轮

- 背景：宿主改为后台代理后没有 Dock 图标，用户需要常驻入口打开偏好设置。
